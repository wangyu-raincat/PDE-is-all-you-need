# T05c 第 0 问：这批测温数据遵循什么传热规律？

## 目标
把“从沉睡数据中识别物理方程”放到演示最前面。现有 `heat_identify` 已在 4 个预设结构（`pde_discovery/real_heat_refined.py` 的 MODEL_NAMES = D, D+h, D+c, D+h+c）中用训练记录拟合、开发记录选模，但它藏在工具后台，5 个决策问题里没有一个直接问“规律是什么”。

## 步骤
1. 新增决策问题 Q0（四根增材杆 xn/xp/yn/yp 逐根回答）：
   > “这批增材杆测温数据遵循什么传热规律？哪些结论可靠？”
2. 答复内容（全部来自工具返回值）：
   - 候选结构表：4 个候选各自的拟合是否成功、Jacobian 秩、开发 RMSE、是否在近优集合（1.05 倍规则）、最终选中谁及按什么规则（项数最少优先）。
   - 选中方程用公式写出：θ_t = D·θ_xx − h·θ + c，并给出每项物理含义（轴向导热 / 侧面散热衰减 / 加热或环境漂移项）与单位。
   - 留出验证：读取既有 `heat_holdout_summary`，给出逐记录相对 L2、RMSE 与两种基线对比（不重跑最终评分）。
   - 可靠性分级：结构与预测——可靠（附留出证据）；单个系数 D、h——受可识别性限制（引用 T05b 的证据与相关系数），并链接 Q1。
3. **对照：无物理先验的 L1 稀疏发现**（只用训练 + 开发记录）。用仓库已有的 L1 引擎与候选库 `1, θ, θ², θ_x, θ_xx`（见 `experiments/MENDELEY_REPORT.md` 所用方法），对四根增材杆的编号 1/2 跑一次，如实报告找到的项。在答复中并列“无先验发现”与“物理先验约束选择”，并说明最终采用哪一个及原因。不得使用编号 3–5 参与选择；若 L1 结果不稳定或含非物理项，照实呈现。
4. Q0 生成完整 decision trace（候选表、开发选择、留出证据、可识别性链接），可用 `decision_trace_get` 展开到原始 CSV 与代码行。
5. 更新 `deepseek_acceptance --decision` 为六问（Q0–Q5），结果写 `verification/decision_v3/`，保留 v1、v2。

## 措辞约束
对外说法为“在物理先验约束的候选结构中识别方程，并用留出数据验证”，不得写成“从任意数据自动发现任意 PDE”。项目在 Burgers/KdV/KS 公开基准上的严格结构恢复为 0/3，若答复提到通用发现能力，须同时给出这一事实。
