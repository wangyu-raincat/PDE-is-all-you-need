# T09 提交文档

初赛要求两份材料，按官方条目逐项对应，不缺项：

## 文档 1：开发设计文档（Word）
章节固定：1 项目概述（痛点、目标用户、价值）；2 整体方案设计（架构图、执行流、技术选型）；3 知识图谱构建方案（本体、ECAOI 算法、标准对齐、增量更新、评测结果）；4 智能体构建方案（角色、Skill 三层、MCP 工具表、检索-推理双驱动、决策溯源）；5 原始数据说明（资产清单、来源/DOI/许可/署名、模态分布、沉睡度、划分）；6 数据处理说明（解析、去重、引文定位、冲突、P0/P1/P2）；7 实验与结果（本体评测、决策问题结果、Nexent 实测）；8 适用范围与限制；9 复用与推广（模板、迁移示例）。

## 文档 2：Nexent 平台智能体设计说明
整体设计思路；每个 Agent 的完整配置（模型信息、提示词摘要、工具、Skill、知识库、max_steps）；调用关系图；调试迭代经验（来自 T08 ITERATIONS.md）；示例问答截图（来自 T08）；随附文件说明（agent JSON、Skill ZIP、知识库文件清单、MCP 服务启动方式与工具清单）。

## Codex 步骤
1. 内容以 Markdown 源写在 `competition_agent/deliverables/src/`，由脚本生成 .docx（python-docx，统一样式：标题、正文 11–12pt、表格样式、图注编号），替换现有 `docs/PDE多智能体开发设计文档.docx` 的 README 直转版本。
2. 图：架构图、执行流、调用关系图用 Mermaid 渲染为 PNG（或 matplotlib 绘制），截图从 T08 目录引用。
3. 所有数字从 verification 目录的 JSON 自动填入，避免手抄出错；脚本输出“数字来源对照表”供人工核对。
4. 篇幅：评审读得完为准，正文控制在 25–35 页，细节放附录。

## 人工
通读一遍，核对截图与数字；确认队伍信息、作品名称。
