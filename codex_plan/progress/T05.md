# T05 制造决策、检索与证据追溯

在主目录从 `competition/nexent-multi-agent` 的 `23b659f` 建立 `comp/T05-decision`。本地 DeepSeek 运行器和真实 MCP 服务覆盖 PLAN §2 的五个问题。报告中的测量与拟合均来自作者公开增材杆数据；复用现有案例容器仅用于保存证据、版本和事件。

## 五个问题的实测结果

| 问题 | 决策与来源 |
|---|---|
| xp 与 xn 的热扩散特性 | 固定 D+h+c，分别拟合两杆的 5 条完整记录。xp 的平均 D 为 4.596×10⁻⁶，xn 为 2.361×10⁻⁶ m²/s。两均值差 2.234×10⁻⁶ m²/s 超过两组中较大的极差 1.439×10⁻⁶ m²/s。证据包含论文第 3 页及 bbox、作者源码分支行号、XLSX 的试样和单元格、逐次 CSV、开发选模和六份历史留出评分。只支持这两根杆在所测条件下的描述性比较。 |
| 材料输入 | 四根杆的测试记录可追溯。当前适合探索性仿真；转作材料输入还需逐次风速、加热和复位记录、独立试样与标准对照。 |
| 标准对齐 | 六点瞬态记录在实测边界下拟合四个内点。GB/T 22588-2008 使用闪光法；方法差异为 `different_method_from`，热扩散系数可按 `comparable_quantity` 比较。目录级对齐待操作员确认。 |
| 同杆直径冲突 | 验收时追加明确标为自制的资料。作者源码的 6.287 mm 与自制资料的 7.9 mm 同时保留，暂停业务使用并建议重新测径。 |
| 正式本体变更或最终结果调模 | 返回操作权限规则和原文位置，转本地操作员审核。该轮只记录决策，未改正式本体或运行数值工具。 |

## 工具、执行与导出

- `competition_agent/decision/retrieval.py` 使用 T03 原始块和位置。向量通道是本地训练的轻量中英 LSA embedding，采用中文双字、英文词、领域别名和固定随机种子；此次索引为 245 块 × 64 维。BM25 复用现有实现，图谱通道读取 T04 增量版本与状态，并把工作表中的试验编号连接到对应测温 CSV 的真实列名。三路按 RRF（常数 60）合并，返回各路名次与引用。
- `kg_query` 与扩展后的 `evidence_path` 共用类型约束遍历。示例模式为 `["Specimen","has_test","Experiment","records_field","ObservationField"]`。新资料先走 `ontology_induce`，读取 `ontology_review_queue`；标准查询直接调用 T04 的 `standard_align`。
- `heat_repeatability(group)` 返回每次拟合的 D/h/c、单位、均值、极差、样本标准差（分母 n−1）和原始 CSV 位置。五次均独立使用预设支持 D+h+c。原训练/开发的选择沿用 `heat_compare` → `heat_identify`。编号 3–5 已查看，仅另作描述性复测离散度计算。历史评分通过 `heat_holdout_summary` 只读获取。合成自检仍走原来的 `pde_identify`。
- `decision_make` 最多检索两轮，有证据缺口时调整查询或提议实验。规则文件为 `competition_agent/decision/rules.yaml`。模型只能从工具生成的可定位解释中选择并排序。`case_handoff` 返回原因及验证工具，`decision_trace_get` 核验 SQLite 事件链与决策摘要，展开规则、模型、跨资产路径和引文。离线 v2 bundle 含 6 个智能体、6 个 Skill ZIP 和 26 个 MCP 工具。
- `competition_agent/multimodal/__init__.py` 对 PDF 搜索投影中的控制占位符以等长空格处理，保留原始块、原文和坐标。这样真实论文可以通过预处理，同时继续隔离不合格的外部文本。

复现时在主目录运行，真实模型验收使用空输出目录，密钥仅读取 `DEEPSEEK_API_KEY`。

```powershell
$py = 'competition_agent/build/t02-env/Scripts/python.exe'
& $py -m competition_agent.deepseek_acceptance --decision --output competition_agent/build/T05/reproduce --max-model-calls 5
& $py -m competition_agent.decision --directory competition_agent/build/T05/release/runtime --case-id $case --output $knowledge
& $py -m competition_agent.decision --directory competition_agent/build/T05/release/runtime --trace-id $trace --output $json
```

`$case` 与 `$trace` 取自归档决策记录。Nexent 导入清单和切片说明见 `verification/decision_v1/knowledge-manifest.json`。本次导入用的逐块 UTF-8 文本及本地向量索引在 `build/T05/release/knowledge/`。每个文件对应一个原文块，保留父块位置，索引文件不作为知识文本导入。

## 适用范围与限制

五个问题检验工程流程。向量模型使用本地语料，未测通用语义召回率；PDF 方法描述、草案边、待核实的标准映射均保留各自来源与状态。测得同杆离散度不能量化总体材料差异。在线 Nexent 平台尚待 T08 实测。


## 验收与用量

- 最终验收运行目录为 `competition_agent/build/T05/release/`。DeepSeek 五问全部通过，5 次请求、22 次 MCP 工具调用，输入 1,867、输出 86、合计 1,953 token。逐问记录、原始模型输出以及从 SQLite 回读核对的五份 trace 均已存入 `competition_agent/verification/decision_v1/`。第 1 问可定位 10 条测试及其中 6 条已有留出评分。
- 开发期共执行四轮验收。最初检索探针在模型请求前停止，原因是泛化问题的前 12 个融合结果没有覆盖三路；将通道探针改为明确询问 xp1 的 TC1 列，五个业务问题保持原文。其后两次五问运行和最终运行均通过。合计 15 次 DeepSeek 请求、72 次 MCP 调用、5,523 个输入 token、258 个输出 token，总计 5,781。逐轮见 `usage.json`。
