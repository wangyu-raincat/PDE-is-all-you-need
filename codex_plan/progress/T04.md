# T04 本体归纳与人工标注准备

分支 `comp/T04-ontology`，起点 `c95a025`（已合入 T03）。已交付算法第 1–6 步的本地流程。使用已有 t02-env，在真实资产上得到 205 条不同三元组，1 条进入草案、204 条进入审核队列、0 条低分丢弃。这里的数量是抽取结果，准确率尚待人工标注。

| 步骤 | 实现与实测范围 |
|---|---|
| 种子本体 | ontology/seed.yaml 定义 16 类、14 种关系，以及主语类型、宾语类型和最大基数。 |
| 标准术语 | ontology/standards.yaml 按任务卡已核实的目录信息登记两个 GB/T 版本和一个 ASTM 版本。未提供的日期或章标题留空。方法比较使用 different_method_from、comparable_quantity。 |
| 多路抽取 | E1 从增材 CSV 表头、manifest、作者源码几何参数及 AdditiveRodResults 的列头生成候选。E2 解析论文中 xp 的命名示例、方向陈述及带单位的数值表达。E3 实际使用环境密钥，向 DeepSeek 发送论文命名段和两条自制卡方向陈述，提示包含种子和三个自制例子。无密钥时跳过。 |
| 校验 | 每个候选引用来源哈希、文件、位置和逐字原文。E3 引文未命中时直接丢弃并记录原因。检查类型、几何量单位和单值冲突。xn 的两个方向候选都保留在队列。 |
| 评分 | logistic 输入为独立抽取器数、不同文件数、约束通过、术语命中及抽取器先验。同一三元组 xn/has_test/xn1 有 E1 一票、源码与 XLSX 两份文件支持。默认权重与先验是启发式初值，缺少人工开发标签，本次未拟合。fit_weights 提供带 L2 收缩的开发集拟合入口。 |
| 分流 | 约束失败或分数低于 0.35 进入丢弃审计。达到 0.75 且无单值冲突及审核标记才进入按内容哈希标识的草案，其余进入队列。排序采用 4p(1-p) 乘以节点覆盖五类决策问题关系的比例，覆盖率是中心度代理，未测实际解锁收益。 |

本次草案为 xp 的较高孔隙类别。草案快照和每一条候选的证据保存在 `competition_agent/verification/ontology_induction/induction.json`。相同来源哈希只计一份文件，两个文件可以来自同一作者或同一次实验。单位检查限于种子配置的直径、长度、密度，冲突比较按对象标签，不作通用单位换算。

## 人工标注

从 205 条候选中按关系轮取、固定随机种子 42 选出 100 条。固定包 `competition_agent/verification/ontology_induction/packet.json` 只显示三元组及原始证据。两位队员各自使用相同文件和不同 reviewer 名，逐条判断支持、不支持或不确定，可写备注及修正。每答完一条即保存，重新运行可续标。应独立完成后再比对结果。

在仓库根目录运行（PowerShell）：

```powershell
$py = 'competition_agent/build/t02-env/Scripts/python.exe'
$packet = 'competition_agent/verification/ontology_induction/packet.json'
& $py scripts/competition_annotate.py label $packet competition_agent/build/T04/labels reviewer_a
& $py scripts/competition_annotate.py label $packet competition_agent/build/T04/labels reviewer_b
```

两条命令分别由两人使用。标注日志绑定包的 SHA-256。候选集上的标注可用于候选正确性判断；后续测全语料召回率还需要标注员查找抽取器遗漏的事实。人工标签、校准权重、一致性、对照结果和评测报告均待后续阶段。
