# 独立实验设计静态审查

审查范围：`protocol.json`、`engine.py`、`fixtures.py`、`run.py`，并查看相关测试源码。只读代码，未加载公开观测、未生成最终角色、未运行发现或评分。以下审查发生在实际套件 prepare 之前。

## 结论

当前设计能够进行一次有边界的比较：固定 IRL1 为晋级候选；全部方法使用同一九项库、训练归一化、去偏规则、开发选模和前向求解器。旧公开数据明确标为回顾性，解析精确导数作为特权对照，不进入晋级依据。现有 gate 的主体逻辑与协议一致。下述两项初审问题已在实际 prepare/fit 之前修正，并完成只读复核；目前没有发现阻止按该协议开始实验的实施问题。回归测试必须另有通过证据才可考虑合入。

## 初审问题与准备前复核

**复核状态：两项均已处理。** `expected_ids()` 枚举全部 63 组合；`complete_records()` 校验数量、唯一性及集合相等，冻结完成、冻结验证和 gate 均调用它。缺项/重复/未知 ID 的 gate 返回 false。`verify_freeze` 另核对模型路径、文件内 ID 和 suite/case/backend/trajectory-count/method 与 ID 一致。协议中的精确导数说明已改成导数与谱投影的联合对照，并明确积分/点态还有回归形式差异。以下保留初审发现，供追溯修复原因。

1. **验证完整的配置集合，不能只验证数量。** `run.py:verify_freeze` 目前只检查记录数量为 63 和各文件哈希；`promotion_gate` 用字典建立配对而不拒绝重复 ID、不验证所有预定组合。重复或漏项可能被覆盖或漏检，不能据此保证全部预定条件都进入 gate。建议根据常量生成唯一 expected-ID 集合，冻结验证、评分入口和 gate 均要求集合完全一致、长度相同、ID 唯一；并校验模型内的 ID/角色/方法/轨迹数与记录一致。缺项、重复、错误配置及未知配置应明确拒绝或 gate=false，不能输出 eligible。

2. **修正精确导数对照的解释。** 协议当前写“Pointwise exact versus estimated isolates differentiation”。实际 estimated 分支先投影观测场，并对 `u²`、`u³` 和 `u*u_x` 做谱去混叠；exact 分支使用原解析场与直接乘积。Cole–Hopf 场不是有限带宽，因此差别不仅是求导，还包含场和候选库的投影/乘积处理。应写成“解析场及导数相对于数值投影和求导的联合上限对照”；不要用该比较声称单独测得纯导数误差。积分与点态的比较还同时改变时间回归形式。

## 已核对一致的部分

- 配置为公开 `3 cases × 3 methods = 9`，解析 `3 families × 3 backends × 2 trajectory counts × 3 methods = 54`，总计 63。三种方法均报告；不按最终表现改选晋级方法。
- 每族有 3 条训练、2 条开发、2 条最终轨迹。训练、开发和最终种子范围不重叠，参数相同、初值不同；不把单条轨迹的相邻窗口伪装成独立实验。种子是预先公开的确定性规则，不是秘密盲测；同族最终初值仍来自有限四模态族。
- 同一 backend 中，单轨迹和三轨迹使用相同总回归行数。预算根据可用行数决定，不使用场值或误差；三轨迹各分配相同数量、等权进入 pooled RMS。不同 backend 的行数可以不同，因此不能把跨 backend 的差别全归因于导数。
- 重加权目标的变量变换正确：用 `X/weights` 拟合，再将解除以 weights，等价于加权 L1。adaptive 权重只由训练 ridge pilot 决定；IRL1 每个 alpha 从同一 pilot 独立开始，固定五次更新，没有跨 alpha warm start 或路径频次投票。
- 开发选择用两条轨迹等权 MSE 的平方根；固定近优容差后优先少项。参考项和最终分数不进入拟合或选择。候选内部为展示而排序，不等于拿跨 lambda 的带惩罚目标选模型。
- 新解析 final 只在 `verify_freeze` 成功后生成；public final 只在该入口之后以数组读取。预先对文件求字节哈希不是读取其数值来选模。Cole–Hopf 时间导数通过解析商法则得到，不从已发现方程的 RHS 构造。
- 空 selected 模型会得到全部参考项缺失、预测失败，不能靠“多余项为零”绕过 gate。逐配置禁止已精确恢复的 plain 退化，加上至少一个严格提升，已逻辑蕴含非 oracle 精确恢复总数不下降，不必另加一个不同标准。
- 公开精确恢复至少 2/3、多余项总数最多 2、漏项与预测失败不增加，以及系数与预测容限均已实现。`pointwise_exact` 被排除出晋级依据，oracle 成绩不能独自触发晋级。
- `merged` 固定为 false，数值 gate 成功仅返回 `eligible_for_review_only`。这是正确的保守边界；它尚不证明回归测试通过。

## 需要在报告或最终核验中明确

- 系数门槛逐配置检查；当前预测门槛检查两条最终轨迹相对误差的**平均值**，不是逐初值最大值。每条预测分数和失败仍分别保留。若准备采用逐初值门槛，应在运行前写入协议并实现，不能查看结果后选择更有利的聚合方式。
- 本轮没有噪声，只能支持干净解析/公开数值数据上的方法比较；不能据此建立真实测量抗噪性能或通用 PDE 唯一可辨识性。
- 54 个解析模型共享仅 3 个方程族和各自同一组开发/最终初值，不能当作 54 次独立统计试验。门槛是工程接受标准，不是统计显著性检验。
- 新增最小工作流测试应覆盖：缺/重复配置拒绝、全部冻结前禁止 final 读取/生成、冻结源/数据/模型篡改拒绝、无候选记录保留、最终观测只改变评分不改变模型、oracle 改善不能让非 oracle gate 通过、单/多总行数一致。
- 现有 gate 只负责数值收益；合入之前必须同时核验原有 128 项及新增回归检查，并保存结果对应的代码哈希。若数值 gate 未通过，保持原项目作为活动基线，不合并实验算法。
