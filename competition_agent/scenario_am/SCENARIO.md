# 增材制造实验数据资产与热物性决策

把实验室散落的测温记录、作者方法源码、实验说明和已冻结模型连接起来，让材料工程师查到系数的原始依据、工艺工程师判断仿真输入是否可靠、质量人员追溯数据来源与验证范围。多年测温数据散落、参数口口相传、工艺仿真缺可信材料输入、复测成本高，是本场景针对的业务问题；这里没有测量节省成本或工时。

## 资产与运行

运行 `python -m competition_agent.scenario_am.catalog` 生成本地资产目录。目录包括两处数据目录的全部文件，以及相关协议、报告和冻结结果 JSON；表格行数不含表头。扫描只做字节哈希、CSV 表头和行列计数，不用于拟合。当前 47 个原始 CSV 中，26 个用于训练/开发，21 个已用于最终评估不可再当盲测，确认从未使用的本地 CSV 为 0。历史 `UNUSED_DATA_METADATA.md` 是首次评分前的记录，以后续 `ADDITIVE_REPORT.md` 的使用状态为准。

`competition_agent.preprocess.prepare_am_catalog()` 返回 CSV 头部和 manifest 的可定位元数据证据，不返回温度正文。数值计算单独走 `heat_identify('xn')`，从编号 1 拟合、编号 2 选模；`split` 仅接受 `train`。支持 xn/xp/yn/yp 和 50/75/100 与 ss/al/cu 的九个组合。调用已有公开读取、候选拟合、条件预测和评分函数，按冻结协议的 1.05 倍近优规则复现四种预设结构选择，不调用最终评估、不写实验产物。对旧九组比较的是 refined_heat 的物理先验模型，不冒充 MENDELEY_REPORT 中早期稀疏方法。

`heat_holdout_summary('all')` 只读返回增材 12 条既有评分；指定单组返回该组记录。`heat_compare('xn', 'xp')` 比较两组训练拟合的系数。所有结果携带 asset_id、source_id、原文引文、文件位置和字符跨度；manifest 关联原始 CSV 哈希，冻结模型关联已有评分。数值工具不会执行资料内指令。

## 五个决策问题

1. xp 与 xn 的热扩散特性是否存在可辨别差异？沿杆编号、构建方向/孔隙类别、作者几何源码、CSV、拟合模型和留出评分逐项查证；当前只能比较有效系数点估计，不能给出显著性结论。
2. 能否用作工艺仿真的材料输入，还缺什么实验？可提供条件预测参考；需补充逐次风速、加热与重置日志、重复工况和标准方法对照，不能仅凭低误差认证材料物性。
3. 瞬态对流法与国标闪光法如何对齐？本任务建立来源入口；标准条款对齐留给后续任务。仅登记标准编号、条款、标题和自写短摘要，不复制标准正文。
4. 同杆直径出现冲突怎么办？保留双方来源和位置，请材料/质量人员复核，不能静默覆盖；作者几何参数见源码第 223–250 行。
5. 能否自动把新关系写入正式本体，或用最终验证结果调模型？沿用人工本体审核边界；本工具拒绝非 train 拟合角色，留出接口只读取既有结果。

## 适用范围与限制

方法名称为“给定实测边界的四内点条件预测（物理先验 D+h+c）”；四种候选中 D 必选，h/c 可选。测量六点，完整实测两端作为输入，四内点评分且排除首帧，不是未知边界自由预测。h 是有效衰减率，c 可补偿模型缺项，系数不是物性认证。当前接口无 bootstrap 区间，训练半段诊断不是置信区间；低误差不证明唯一方程、严格同工况或跨装置泛化。全部已有留出已查看，复现不会产生新的盲测证据。

平台部署与 Nexent 实测属于 T08；本任务提供本地工具与角色绑定。完整工作流和标准/图谱推理由后续任务接入。

本地历史 JSON 使用 CRLF 换行，而历史冻结索引使用 LF 版本哈希。工具分别核验实际字节及仅 CRLF→LF 后的哈希，返回 `match_mode`、实际和历史哈希；任何其他内容变化均拒绝。原始 CSV 哈希仍必须与 manifest 完全一致，不做换行归一化。可用 `python -m competition_agent.preprocess --am-catalog --output competition_agent/build/am-metadata.json` 导出元数据证据包。
